# 既存Web作品のモバイル受入条件 2026-10-13

## 一次資料と判断

[itch.ioのHTML5配信仕様](https://itch.io/docs/creators/html5)はブラウザ配信の経路と画面サイズへの適応を説明し、Mobile Friendlyは動作確認した作品で使用するとしている。これはWeb技術で制作する方針に適合する配信経路の実在を示すが、当作品の需要や利用者数を示さない。アカウント作成・投稿・新しい配信先への移行は行わない。

[MDNの入力方式](https://developer.mozilla.org/en-US/docs/Games/Techniques/Control_mechanisms)はデスクトップのキーボード/マウスとモバイルのタッチ等を分けている。[W3CのTarget Size Minimum解説](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)は24×24 CSS pxまたは規定の間隔・代替操作などの例外条件を説明する。単に盤面全体を縮小して枠へ収めるだけでは操作性を証明できない。法的な適合判定はせず、内部の操作受入基準として利用する。

今回のブラウザ画面ではn目並べの大きい盤面やMineRushのセルが小さい。現在の技術結果からはimprove、需要・収益・人間の反応はunobserved。24pxの基準を満たす同等の操作導線を設ければ、盤面を維持したまま誤操作を減らせるという仮説を置く。需要改善は未検証。

## 独立した次タスク

T-web-legacy-mobile-input-acceptanceを、既存4作品の基本ルール/保存検査の完了後に実施する。新作とUnity再開には置き換えない。

1. 一作ずつ、390×844と1280×720で実際の操作対象の矩形を測る。24×24 CSS px未満なら間隔か同等の代替操作を証跡付きで検討する。
2. 縮小で盤面を切らず、選択したセルを識別してキーボードでも確定/取消できることを確認する。確認ダイアログのフォーカスと復帰先も確認する。
3. 保存対象/非対象/失敗表示を画面の案内と一致させる。物理タッチ、端末傾き、Safari、人間評価をブラウザ自動操作から分ける。
4. 未実行を成功扱いせず、実物受入までrelease=nullの開始リンクを追加しない。公開指標はnullのまま観測待ちとする。

既存工程をこの調査へ置き換えず、今回同じWIP1でIce Slide→MineRush→n目並べの実装・検査へ反映した。利益や制作数を成果指標として推測しない。
