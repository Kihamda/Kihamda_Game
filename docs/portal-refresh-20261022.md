## 配信と復元

本人の今回の直接指示によりポータルのトップ・紹介・案内の本番刷新を許可した。既存のゲームHTML4件とMineRushの版をFTPS/HTTPS照合して保護する。成功した同じmain CIの保管パッケージだけを使用し、ゲームHTML・service worker・不要な管理ファイルは送信しない。

portal_publish.pyは旧ターゲットをbefore/へ保存し、対象の事前ハッシュを保持する。ハッシュ付き共有アセットの異なる内容への上書きを拒否し、新しい依存素材・画像を先行、ホームHTMLを最後に切り替える。STOR前のjournal・一時ファイル読戻し・変更直前照合・rename後照合を行い、最後に公開ファイルと保護対象を再検証する。リモートのファイルを削除しない。

問題時は配信runのportal-delivery-<ID>を取得し、package・portal-recovery・portal-transaction.jsonを保持する。同じFTPルートに対し次のコマンドで旧バイトを戻せる。元journal/backupはコピーしてから使用する。

```powershell
python business/ops/portal_publish.py <展開先>/package <展開先>/portal-recovery <展開先>/portal-transaction.json --recover
```

復元前にpackage・transaction・独立したbackup receipt・旧バイト・現在の本番を照合する。第三者の変更を上書きしない。旧依存アセットは削除していないため旧ホームから先に戻せる。新設ファイルは残し、復元後は旧ホームと保護対象のHTTP・ブラウザ操作を別途確認する。FTP自体はCASを提供しないため、直前照合後の外部更新との競合を完全に防ぐものではない。
