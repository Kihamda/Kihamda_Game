# GravityBallの最高スコア読込案内

2026-10-15の13時枠。既存T-web-gravity-score-read-noticeを継続し、新作は追加していない。

旧実hookでgetItemを拒否するとbest=0になり、読込エラーを示す値もなかった。不正値も0へ変換していた。現行版は未保存の0点、読込拒否、不正形式を区別し、読込異常時のcanvas最高値を「未確認」と表示する。再試行ボタンを設け、正常値を読み込めた時だけ読込案内を解除する。不正な元データを読込だけで削除・修復しない。

読込異常中の得点更新は未保存として保持する。復旧時に既存の最高値と画面内最高値の大きい方を保存し、読めていない高得点を低い値で上書きしない。過去の値が未確認の時は新記録成功を返さない。書込拒否の再試行、同点更新、削除失敗の再試行は維持した。

実hook回帰で拒否・不正形式・正常な空データ、500点の読込拒否中の100点更新と復旧、元不正値保持と正常値への復旧を確認。既存5ステージ幾何ルート、遷移、入力、タイマー、最高スコア保存の回帰も成功。型・ESLint・Viteビルド成功。

専用Chromeの127.0.0.1:4217で390×844と1280×720を検査した。Storage.prototype.getItemの対象キーだけを拒否し、SPAのルート往復で実hookを再マウントした。CDPの新文書スクリプトAPIは未対応だったため、導入せず同一文書のfixtureに切り替えた。通常利用環境の拒否を観測したものではない。

両寸法で拒否継続・API復旧・不正形式保持・正常値復旧を確認した。390はクリック、1280はEnterで再試行。復旧すると案内とボタンが消え、ゲームへフォーカスが戻った。800/900/950は検査用に注入した値で利用者の記録ではない。再読み込み後に正常値と案内なしを確認した。390のボタン348×44px、横はみ出しなし。APIは復元済み。
