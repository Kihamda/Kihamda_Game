# GravityBallのキーボード操作と模擬タッチ

2026-10-14の07時枠で、同じT-web-legacy-mobile-input-acceptanceをn目並べに続いて進めた。

ゲーム画面にフォーカスしたときの矢印キーで重力方向を上下左右へ切り替える。Enter・Spaceは既存の開始・再挑戦処理を使う。フォーカス枠とキーボードの説明を追加した。2本以上の指では先頭の指だけを使って重力を変えないようにした。

実際のAppハンドラーを呼ぶ回帰検査で4方向の符号と強さ0.3、ページスクロール抑止、遷移中の操作無視、Space再挑戦、単指と複数指を検査した。既存の5経路・最高スコア形式/保存失敗・移行中の再開始抑止・二重加点・終了時保存・タイマー取消の検査も成功。

最終production版をChromeの390×844で操作し、単指ドラッグの模擬イベントが右向きの重力{x:0.3,y:0}へ変わること、複数指移動とキャンセル後にその向きが変わらずplayingのままであることを読み取り確認した。4方向のキーでもそれぞれ{-0.3,0}/{0.3,0}/{0,-0.3}/{0,0.3}になった。ゲーム状態を注入・書き換えず、UI入力後の状態だけを読んだ。実測値はbusiness/unity/evidence/gravity-input-20261014-0700.json。Chromeは390で265.5×318.6px、1280で500×600px。横のはみ出しなし。Codex内ブラウザでは390で269×322.8px、1280で500×600pxを確認した。初回のviewport変更直後に旧縮小率を読んだ値は確定値に使わず、再描画後の寸法を使用した。

Codex内ブラウザはInput.dispatchTouchEventが未対応だったため、Chromeの検査用タブで模擬入力を行った。物理タッチ、Safari、iOS許可、実際の傾き、人間の操作性・面白さは未確認。今回は新しい全5ステージクリアを主張しない。保存条件は全5ステージ完了時の最高スコアのみ、途中保存なしのまま。Unity、release=null、事業指標は変更しない。本番配置・追加PRはしない。
