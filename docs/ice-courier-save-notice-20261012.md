# Ice Courierの保存失敗案内

2026-10-12の01時枠で、既存T-ice-courier-touch-polishのF3を継続した。保存処理が失敗した直後に配送を完了すると、保存不可の案内が配送完了メッセージで消えていた。ルートを開き直した場合も警告が消えていた。

保存警告を通常の案内と分け、配送完了・Undo・Restart・Resume後も残すようにした。保存APIが例外なく戻った時だけ警告を消す。以前の保存を読み出せたことを、新しい保存の成功とは扱わない。保存形式、盤面ルール、操作配置は変更していない。警告と共に表示する完了・再開文を短くし、既存の72px高の案内欄に収めた。

## 検査

Unity 6000.3.23f1で、修正前のPlayModeは既存検査1件が成功し、追加した2件が意図した箇所で失敗した。配送完了による警告の上書きと、Openによる消失を再現した。修正後はPlayMode3/3、EditMode10/10、Validateが成功。画面検査用メニューを追加した最終ソースでもPlayMode3/3が成功した。

保存関数に例外を注入し、保存できなくても配送・Undoが動くこと、保存API復旧後の警告解除と再開、古い保存の再開後も警告が残ること、再開前のUndo履歴が戻らず新しい一手は取り消せることを確認した。テストは実行前のPlayerPrefsの有無と値を退避し、終了時に戻す。

Editorの実画面でも、テスト用の「Kihamda → QA → Simulate save failure」で例外を注入した。このメニューはEditorのテストコードだけにあり、PlayerPrefsを書き換えない。画面上の方向ボタンで最初のルートを2手で完了し、警告が残ることを確認した。
